  Item 2: Performance — 3 Approaches

  A) Frontend-first — Profile and fix rendering (memoization, virtualization,
  image caching). Fast to start but useless if the bottleneck is the API.

  B) Backend-first — Profile Home/VOD/Search API endpoints, add caching,
  optimize queries. Equally blind if the bottleneck is rendering.

  C) Dual-track profiling (recommended) — Run both investigations in parallel
  using subagents:
  - Track 1: Frontend profiling (Android Profiler, Xcode Instruments, Chrome
  DevTools) on the three screens
  - Track 2: Backend profiling (API response times for the three endpoint
  groups)
  - Then fix wherever the bottlenecks are found, prioritized by impact

  Approach C is the only one that doesn't risk wasted effort given that the root
   cause is unknown.

⏺ Design — Part 5: Workstream B3 (Fixes)

  Fixes are conditional on profiling results, but based on the audit, three
  high-probability issues already stand out:

  Likely fix 1: bayit-search cold starts
  If confirmed: set minInstances=1 on the bayit-search Cloud Run service. One
  line change in the deploy config. Eliminates 1-2 minute cold start for first
  search per session.

  Likely fix 2: Sequential shelf API calls
  If Home/VOD screens are fetching shelves one-by-one, fix is parallelization:
  - Android: wrap shelf calls in async {} + awaitAll()
  - iOS: replace sequential await chains with async let bindings
  - Web: replace serial useQuery calls with useQueries (TanStack Query parallel
  fetching)

  Likely fix 3: Missing cache on hot endpoints
  If Home/VOD endpoints have no cache layer: add Redis TTL caching in the
  bayit-content service for shelf listings (content changes infrequently —
  5-minute TTL is reasonable). The service already has Redis infrastructure per
  the Olorin ecosystem notes.

  Fixes that will NOT be made speculatively (only if profiling shows them):
  - Image compression pipeline changes
  - MongoDB index additions (schema-locked rules apply to DDL, indexes are
  additive — but still need evidence first)
  - Bundle splitting beyond what already exists
