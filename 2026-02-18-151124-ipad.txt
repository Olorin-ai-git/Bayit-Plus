  iPad Login Screen - Parity Review

  Architecture (How it works)

  The iPad does not have its own @main entry point. It runs through the shared
  BayitPlusApp.swift (line 15) -> ContentView.swift. The auth flow
  (AuthFlowView) renders before the iPad/iPhone split (line 31-33), so the same
  LoginView is used for both iPhone and iPad. The iPad-specific IPadContentView
  only kicks in after authentication (line 35-36).

  Issues Found

  1. CRITICAL - Language showing Japanese instead of Hebrew/English

  The LocalizationManager at LocalizationManager.swift:112-118 restores the
  language from UserDefaults. If no language was previously saved, it defaults
  to .english. The fact that Japanese is showing means either:
  - The simulator has "tv.bayit.localization.selectedLanguage" set to "ja" in
  UserDefaults (someone previously selected Japanese in settings)
  - OR UI_TEST_LANGUAGE environment variable is set to "ja" (line 268-270 in
  BayitPlusApp.swift)

  There is no system locale detection anywhere - Locale.preferredLanguages is
  never consulted. The app hardcodes English as fallback, never matching the
  device language.

  Fix needed: Reset the simulator's UserDefaults, or check Xcode scheme
  environment variables for UI_TEST_LANGUAGE=ja.

  2. HIGH - Placeholder text not localized

  In LoginView.swift:87 and :111, the placeholder strings are hardcoded English:
  - "Enter your email" (line 87)
  - "Enter your password" (line 111)

  These should use localization.t("login.emailPlaceholder") and
  localization.t("login.passwordPlaceholder").

  3. MEDIUM - No iPad-optimized login layout

  The LoginView uses the same layout for both iPhone and iPad. On the iPad's
  larger screen:
  - The form card stretches to full width with only Spacing.xl padding
  - No maxWidth constraint on the card for larger screens
  - The layout could benefit from a centered card with a max width (~480pt) for
  iPad

  4. LOW - Login screen is shared (parity is good)

  Since AuthFlowView is rendered before the device split in
  ContentView.swift:32, both iPhone and iPad use the exact same LoginView. This
  means feature parity is inherently maintained for the auth flow - there's no
  separate iPad login to go out of sync.

  Recommended Actions

  1. Immediate: Check Xcode scheme for UI_TEST_LANGUAGE env var, or reset
  simulator to clear saved Japanese language preference
  2. Localize placeholders in LoginView.swift lines 87 and 111
  3. Add iPad max-width constraint to the login card for better proportions on
  larger screens
  4. Consider adding system locale detection as the initial fallback in
  LocalizationManager.restoredLanguage() before defaulting to English
