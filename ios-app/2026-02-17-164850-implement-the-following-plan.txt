│ Plan to implement                                                            │
│                                                                              │
│ Phase 3: VOD Avatar Interaction -- Enhanced Features                         │
│                                                                              │
│ Context                                                                      │
│                                                                              │
│ Phase 2 delivered text-based free-form dialogue between user avatars and     │
│ movie characters across all platforms (backend, web, iOS, tvOS, Android).    │
│ Panel review (3 reviewers) identified 14 critical+high findings which were   │
│ all resolved. Phase 3 extends this into a voice-driven, spatially-aware,     │
│ multi-character, social experience via 4 workstreams.                        │
│                                                                              │
│ Design Decisions                                                             │
│                                                                              │
│ 1. Audio chunking: Client-side VAD (push-to-talk), send complete utterance   │
│ as single binary WS frame. Existing                                          │
│ enhanced_asr_service.transcribe_child_speech() expects complete audio, not   │
│ streaming chunks.                                                            │
│ 2. Scene analysis: Pre-computed via admin batch endpoint (not real-time).    │
│ Frame extraction + analysis is too slow for runtime. Fallback to             │
│ configurable default position.                                               │
│ 3. Reactions: Text-only with static avatar (no animation). Saves cost and    │
│ latency. Only primary character response gets ElevenLabs + Creatify          │
│ pipeline.                                                                    │
│ 4. Shared sessions: Embed in existing VODInteractionSession with optional    │
│ shared_metadata field (no new collection -- schema-locked compliance).       │
│ 5. Turn timeout: Auto-advance after configurable timeout with countdown      │
│ warning broadcast.                                                           │
│                                                                              │
│ Implementation Order                                                         │
│                                                                              │
│ Workstreams 1+2 in parallel, then WS3, then WS4 (depends on WS3).            │
│                                                                              │
