⏺ Now I see the root cause. The APIClient uses keyDecodingStrategy = 
  .convertFromSnakeCase (line 52), which automatically converts JSON keys like
  "profile_id" to "profileId". But BiometricConsentStatus also defines explicit
  CodingKeys mapping profileId = "profile_id". These conflict: the decoder
  converts "profile_id" to "profileId" in the JSON, then the CodingKey asks for
  "profile_id" (its explicit stringValue) which no longer exists.

  Other models survive because their properties are Optional (missing key =
  nil), but BiometricConsentStatus.profileId is non-optional String, so it
  throws keyNotFound.

  The fix is to remove the redundant explicit snake_case mappings from the
  CodingKeys in AvatarMeshModels.swift.
