│                                                                              │
│ Context                                                                      │
│                                                                              │
│ Bayit+ backend is a FastAPI monolith on Cloud Run with 157 route files, 215+ │
│  services, and 24 WebSocket route files (~5K lines). All WebSocket state     │
│ (connection tracking, room membership, active sessions) is in-memory only -- │
│  meaning Cloud Run multi-instance scaling silently breaks multi-user         │
│ features like watch parties, chess, and channel chat. Users on different     │
│ instances never see each other's messages.                                   │
│                                                                              │
│ Extracting WebSocket routes into a dedicated bayit-ws-gateway Cloud Run      │
│ service solves this by:                                                      │
│                                                                              │
│ 1. Introducing Redis pub/sub for cross-instance messaging                    │
│ 2. Allowing independent scaling (3600s timeout for WS vs 300s for REST)      │
│ 3. Reducing monolith cold-start time and memory footprint                    │
│                                                                              │
│ Routing: Separate subdomain ws.bayit.tv (REST stays on api.bayit.tv).        │
│ Redis: New infrastructure -- no existing Redis/Memorystore.                  │
│                                                                              │

│ 3.2 Shared code strategy                                                     │
│                                                                              │
│ Do NOT create a separate bayit-shared package. Instead, the gateway imports  │
│ directly from the monolith's app.core and app.models modules via a Poetry    │
│ path dependency:                                                             │
│                                                                              │
│ [tool.poetry.dependencies]                                                   │
│ bayit-backend = { path = "../backend", develop = true }                      │
│                                                                              │
│ This avoids the overhead of extracting and maintaining a shared package.     │
│ Both services live in the same monorepo and deploy from the same commit.     │
│                                                                              │
│ If this creates import issues (circular deps, heavy startup), fall back to   │
│ symlinking specific modules or extracting only app/core/ and app/models/     │
│ into a shared package.                                                       │
