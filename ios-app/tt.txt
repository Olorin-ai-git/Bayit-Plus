⏺ The fix is in. Here's the root cause and what changed:

  ---
  Root cause: pause_ask_orchestrator.py only called _animate_user_safe() when
  avatar.has_voice_clone was True (i.e. voice_clone_status == "ready" AND
  elevenlabs_voice_id set). Your Karate Kid 1 test avatar either hasn't
  completed voice cloning or is using a pre-built avatar without a personal
  voice. With no animation, user_animated_video_url came back as "", and the
  client-side guard in TVPauseAskDialogueOverlayView+Playback.swift (line 11-13)
   correctly skipped straight to character video.

  Fix — two files:

  1. user_avatar_animator.py — added fallback_voice_id: str = "" parameter; uses
   avatar.elevenlabs_voice_id or fallback_voice_id so a default ElevenLabs voice
   can drive TTS when no personal clone exists.
  2. pause_ask_orchestrator.py — changed the condition from if 
  avatar.has_voice_clone to also animate when the avatar has a face image
  (creatify_avatar_image_url or primary_avatar_gcs_path) AND
  MOVIE_INTERACTION_DEFAULT_VOICE_MALE is configured in secrets. Passes the
  fallback voice only when the personal clone is absent.

  After the fix: as long as MOVIE_INTERACTION_DEFAULT_VOICE_MALE is set in
  GCloud secrets (which the generate_karate_kid_qa_videos.py script already
  depends on), the kid avatar will speak in the default kid voice and the full
  sequence — kid video → transition → character response — will play as
  expected. If MOVIE_INTERACTION_DEFAULT_VOICE_MALE is not set, behavior
  gracefully degrades to the previous no-user-video flow.
