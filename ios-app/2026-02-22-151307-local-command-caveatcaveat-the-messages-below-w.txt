⏺ I've traced through the full trivia lifecycle. I can see the bug clearly now.
  There are two interrelated problems:

  Root cause 1: TVTriviaFactsOverlayView.onDisappear calls viewModel.cleanup()
  which resets shownFactIds = []. If the overlay is temporarily removed from the
   view hierarchy (e.g., when state.interactionVM?.activeMoment flips), the
  tracking of which facts were already shown is destroyed.

  Root cause 2: TVTriviaFactsOverlayView's .task calls loadFacts() again when
  the view reappears, which also resets shownFactIds = [] and lastRandomFactTime
   = -.infinity. This causes the highest-priority fact to immediately re-show.

  Root cause 3: Both TVPlayerView and TVTriviaFactsOverlayView call
  updateActiveFact() on time changes -- a redundant duplicate.

  The result: any view lifecycle event that removes/re-adds the overlay resets
  all trivia tracking state, causing the same first fact to appear.

  both:

  1. Timed/scene-specific facts (triggerType == "time") shown within a 30-second

  The bug was that the tracking state (shownFactIds, lastRandomFactTime) was
  getting wiped every time the overlay view was temporarily removed from the
  SwiftUI hierarchy, causing the same highest-priority fact to replay.

  Here's a summary of what was fixed across 4 files:

  TriviaFactsViewModel.swift -- Added loadedContentId guard so loadFacts() skips
   redundant reloads for the same content, preserving the shownFactIds set that
  tracks which facts were already displayed.

  TVTriviaFactsOverlayView.swift (tvOS) -- Removed three problematic modifiers:
  - .task { loadFacts() } -- duplicate call (already done in
  initializeViewModels), and would reset tracking state whenever the view
  reappeared
  - .onChange(of: currentTime) { updateActiveFact() } -- duplicate call (already
   done in TVPlayerView)
  - .onDisappear { viewModel.cleanup() } -- was destroying shownFactIds whenever
   the overlay was temporarily removed (e.g., during interactive moments)

  TriviaFactsOverlayView.swift (iOS) -- Same three fixes applied for parity.

  TVPlayerView+Lifecycle.swift / PlayerView+BodyContent.swift -- Moved
  triviaVM.cleanup() to the player's own cleanup, so it only fires when the
  player is actually dismissed (not when the overlay temporarily hides).
